# Rules for `src/assets/`

- After a remix, every pointer under `src/assets/` is re-uploaded into this project's storage (`lovable-assets create`) and every URL reference rewritten; a pointer carries the previous project's id, so images load in the sandbox but break once published. Two pointers (`nempo-feed-slide-31-gamelan-frame-transparent.png`, `nempo-feed-slide-32.mp4`) have no copy in the repo, so their bytes are downloaded from the previous project's preview host at `https://id-preview--<previous-project-id>.lovable.app/__l5e/assets-v1/<asset-id>/<filename>` before re-uploading; `lovable-assets get` refuses cross-project pointers. `src/data/media-archive.json` and the `media_archive` record keep filenames, checksums and source download URLs; why: migration must copy original files as well as code, and public Cloud Storage is blocked by workspace policy.
- Every media pointer under `src/assets/` also has its real file next to it, code imports the real file, and database image paths point to `public/` files; why: `/__l5e` asset URLs only work on Lovable hosting, so photos must survive deploys elsewhere (e.g. Vercel).
